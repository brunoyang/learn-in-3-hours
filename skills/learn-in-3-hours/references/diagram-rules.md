# 图解规范（手机优先）

## 为什么按手机尺寸画

学习者大多在手机上看。390px 宽的手机减去页边距后，图的实际宽度约 340px。如果按 880 宽的画布画、标签 10px，到手机上就只剩约 4px，完全看不清。这是在一份公开样例上实测到的真实情况。所以默认按手机的实际尺寸来画，电脑上再等比放大（最宽 480px）。

## 尺寸规则

- **viewBox 宽固定 340**，例如 `viewBox="0 0 340 300"`。这样 1 个单位约等于手机上 1px，你写多大字号，手机上就显示多大。高度随内容定，竖长图完全没问题（250–480 之间都常见）。
- **字号只用下面这几个类，不要自己写 font-size**：

| 类 | 字号 | 用途 |
|---|---|---|
| `.t` | 15 | 默认标签 |
| `.t-s` | 13 | 次要说明（这是下限） |
| `.t-b` | 16 粗体 | 节点标题 |
| `.t-h` | 18 粗体 | 图中唯一的主标题或中心词 |

- **颜色修饰类**：`.t-a`（主强调色）、`.t-b2`（第二强调色）、`.t-ok`、`.t-w`（警示）、`.t-m`（弱化）。**对齐类**：`.c`（居中，最常用）、`.r`（右对齐）。多个类可以叠加：`class="t-b c t-a"`。

## 图形类（颜色随主题和深浅色模式自动切换）

- **节点**：`.n`（中性）、`.n-a`（主强调）、`.n-b`（第二强调）、`.n-ok`（正确/安全）、`.n-w`（错误/风险）、`.n-ghost`（虚线分组框）。
- **连线**：`.e`、`.e-a`、`.e-b`、`.e-w`，叠加 `.e-d` 变成虚线。
- **箭头**：`marker-end="url(#ah)"`；彩色连线用 `#ah-a`、`#ah-b`、`#ah-w`。箭头定义由页面统一提供，不要自己写 `<marker>`。
- **实心填充**（圆点、进度条等）：`.fill-a`、`.fill-b`、`.fill-ok`、`.fill-w`、`.fill-m`。
- **不要写死颜色**（`fill="#38bdf8"` 之类），否则深色模式和换主题时会出问题。

## 先讲清因果，再谈好看

机制图最常见的失败，不是看不清，而是**只把名词摆上去，没画出“为什么”**。

真实例子：讲美联储利率走廊的图，最初只画了一根柱子，旁边标着“天花板：常备回购 4.00%”“锚：准备金利率 3.90%”“地板：逆回购 3.75%”。字很清楚，但读者看不懂：为什么有了这三个利率，市场价就不会越线？重画后，每条线都写成“谁的退路 → 所以价格不会越过这里”（“B 的退路：抵押国债找美联储借 → 所以 B 不会付给 A 更高的价”），再加上两头往里挤的箭头和实际成交价。读者就能用自己的话讲出机制了。

所以画每张机制图前，先写一句话说明它要教会什么，写在 `data-teaches` 属性里（学习者看不到，给新读者测试对照用）：

```html
<figure data-block="figure" data-teaches="美联储不直接规定银行间利率，而是给借钱方和放钱方各留一条退路，市场价因此被夹在区间里。">
```

然后检查图里有没有画出这句话中的每一环：谁、做什么、为什么、结果是什么。图里只有名词、没有动词和“所以”，基本就是没讲清。

## 排版规则

- **竖向布局**：流程从上往下走，一行最多 3 个节点。
- **框要装得下字**：节点宽度 ≥ 字符数 × 字号 + 16。中文字约 1 个字号宽，英文和数字约 0.6 个字号宽。例如“Follower · Broker 2”在 16px 下大约需要 170 宽。**标签比框宽，是最常见的缺陷。**
- **两行标签**：写成两个 `<text>`，行距 18–20 个单位。
- **标签间距**：相邻标签之间至少留 8 个单位。
- **一张图只讲一件事**：带文字的元素控制在 12 个左右。图必须展示机制：前后对比、带箭头的流程、结构分层、用台账里真实数字画的对比柱。纯装饰图标不算。
- **图里的数字也是事实**：要进台账，并和正文保持一致。
- **无障碍**：`<svg>` 上加 `role="img"` 和 `aria-label`，一句话概括这张图展示了什么。

## 例外：确实需要横向展开的图

长时间线、宽表格这类确实展不开的图，用横向滚动容器，并用 min-width 保证它在手机上仍是 1:1 尺寸：

```html
<figure data-block="figure">
<div class="scroll"><svg viewBox="0 0 640 220" style="min-width:640px" role="img" aria-label="…">…</svg></div>
<p class="scroll-hint">← 左右滑动 →</p>
<figcaption>…</figcaption>
</figure>
```

## 常用骨架

竖向流程（节点 → 箭头 → 节点）：

```html
<svg viewBox="0 0 340 250" role="img" aria-label="消息从生产者经分区日志到消费者">
  <rect class="n-a" x="95" y="10" width="150" height="46" rx="10"/>
  <text class="t-b c" x="170" y="39">生产者</text>
  <line class="e-a" x1="170" y1="56" x2="170" y2="92" marker-end="url(#ah-a)"/>
  <rect class="n" x="60" y="96" width="220" height="56" rx="10"/>
  <text class="t-b c" x="170" y="120">分区日志</text>
  <text class="t-s c" x="170" y="141">只追加，按 offset 编号</text>
  <line class="e" x1="170" y1="152" x2="170" y2="188" marker-end="url(#ah)"/>
  <rect class="n-ok" x="95" y="192" width="150" height="46" rx="10"/>
  <text class="t-b c" x="170" y="221">消费者</text>
</svg>
```

左右对比（之前 / 之后，或者错误做法 / 正确做法）：两列，每列宽约 150，列中心分别在 x=88 和 x=252；左列用 `.n-w`，右列用 `.n-ok`；顶部各放一个 `.t-b c` 小标题。

对比柱：参考 `assets/example/_work/src/01-compound.html`。柱宽约 48，所有高度按同一比例从台账数字换算，数值标签放在柱顶上方约 8 个单位处。

## 检查

**第一步：渲染检查（脚本）。** `check_course.py` 会在 390px 手机宽度下实测每张图的每个标签：实际字号低于 11px、标签互相重叠、标签比所在的框宽、标签超出 SVG 边界，都算**错误**；低于 12px 算警告。然后查看 `_work/check/shots/` 里的截图（每张图浅色、深色各一张）。

**第二步：新读者测试（判断图有没有讲清）。** 画图的人自己最不适合判断“看不看得懂”，因为他脑子里已经有答案了。所以要让一个没看过正文的新读者只看截图和图注，讲出这张图说了什么：

1. 检查脚本会把所有图写进 `_work/check/figures.json`，每项包括页面、第几张图、`teaches`、图注、浅色截图路径和内容指纹 `hash`。
2. 能派子 agent 时，每 5–6 张图交给一个新 agent。它不需要最强的模型，因为它扮演的是新手。**只给它截图路径和图注，不给 teaches、不给正文。** 任务说明这样写：

   > 你是一个完全没学过这个领域的普通人，正在手机上看课程里的几张图。只用 Read 读取下面这些图片文件，不要读取其他文件、不要搜索、不要用你原有的专业知识补充图里没有的信息。对每张图，根据图和图注用大白话回答（每问 1–3 句）：1. 这张图想说明什么？2. 图里的结果是怎么来的？是什么在起作用？3. 看完还有哪里没懂？图里没讲清楚的，直接说答不出来，不要猜。

3. 拿每张图第 2 问的回答对照 `teaches`：
   - 读者用自己的话讲出了 teaches 的核心因果，记 `pass`。
   - 读者说“答不出来”“说不清”，或者讲成了别的机制，记 `fail`，重画后再测。
   - 第 3 问里剩下的疑问，如果是本页正文已经解释的术语，可以接受；如果恰恰是核心机制，就算没讲清。
4. 结论写进 `_work/reader-test.json`：

```json
[{"page": "01-fed-rate", "fig": 1, "hash": "fd5e4e6d2e9a", "verdict": "pass",
  "reader_summary": "读者对第 2 问的回答要点", "open_questions": "第 3 问的回答要点"}]
```

检查脚本按 `page` 和 `hash` 对照：`fail` 算错误；图改动过（hash 变了）或还没测，给出警告，提示重测。

没有子 agent 时的退路：在重读 teaches 之前，先只看截图，按上面三个问题写下你的回答，并严格要求自己“图里没画的不算”。这比新读者测试弱，交付时要说明。
