# 页面规范

## 片段格式

每页一个文件 `_work/src/<page-id>.html`，只包含顶层区块：`<section|figure|details|div|p data-block="…">`。

构建脚本负责加上：页眉（第几幕、时间位置、本页时长）、页码和标题（取自 course.json）、每个区块的标签（“先想一想”“要点”……）、样式、引用编号、“本页来源”、翻页导航和学习进度。所以片段里**不要**写这些：`<html>`、`<head>`、`<style>`、区块标题、颜色值。

完整示例见 `assets/example/_work/src/`。

## 页与页之间要真的接上

学习者对 AI 生成课程最常见的抱怨是“各章是割裂的”。问题通常不在于没提前一页，而在于**提了一句，却没用上**：锚点写着“第 4 页讲了折现”，接下来的图、要点和例子却换了一套说法。

规则：本页依赖前面某个工具时，要在图、要点或例子里**用那个工具推出结论**。比如讲债券价格下跌，就用第 4 页的折现公式把价格算出来，而不是只画一个跷跷板。比方可以留着，但它是辅助，不能代替前面学过的机制。

检查脚本会对开头部分（lede、hook、anchor、points）完全没引用前页的概念页给出警告；更完整的检查是 SKILL.md 第 6 步的连贯性通读。

## 区块一览

### 概念页（type: concept）

| 区块 | 标签 | 写什么 |
|---|---|---|
| `<p data-block="lede">` | （副标题） | 一句话点出本页要解决的困惑 |
| `hook` 必需 | 先想一想 | 一个反直觉的问题或现象，一两句话；最好让学习者先猜，答案在本页后面揭晓 |
| `anchor` 必需 | 从你已经懂的出发 | 本页依赖前面某一页时（看 research.md 的依赖关系），**先承接那一页**：写明页码，说清上一页留下了什么问题、这一页为什么接着讲。生活经验和相邻领域（给后端工程师讲 Kafka 可以锚在 MySQL 主从上）放在承接之后，或者放进类比。每一幕的第一个概念页也要交代它和上一幕的关系 |
| `<figure data-block="figure" data-teaches="…">` 必需 | （图） | 主图 SVG 加一句 `<figcaption>`，说明怎么读这张图。机制靠图讲，不靠文字讲。`data-teaches` 用一句话写明这张图要教会什么（学习者看不到，给新读者测试对照用；recap、mindmap 同样要写） |
| `points` 必需 | 要点 | `<ul>`，最多 3 条结论，每条约 40 字以内 |
| `analogy` 必需 | 打个比方 | 一个调动身体或日常经验的类比，一两句话 |
| `boundary` 必需 | 这个比方在哪失效 | `<ul>`，写 1–2 个失效点。这些是事实陈述，要进台账 |
| `<details data-block="deep">` 可选 | 深入一层（选读） | `<summary>` 写一个具体标题。放技术细节、公式、配置名、边界情况和来龙去脉。默认折叠，时长单独计算 |
| `selftest` 必需 | 自测（先答再看） | 1–2 个 `<div class="q">`，每个含问题和 `<details><summary>看答案</summary>…</details>`。至少一题要么针对常见误解，要么需要应用而不是复述 |
| `retell` 必需 | 复述挑战 | `<p class="motto">` 放一句 15 字以内的金句，再加一句“合上页面，给朋友讲清……” |
| `recap` 幕末必需 | 本幕小结 | 第 1、2 幕中页数不少于 2 的那一幕，最后一个概念页要加：一张把本幕概念连成网的 SVG，加一两句话 |

### 地图页（type: map）

- 片段只需要写 `lede`、`meta`（必需）、可选的 `route` 和 `figure`（全局鸟瞰图）。
- `meta`：用 `<ol>` 列 2–4 个元概念，每个配一句大白话，说明它为什么是骨架。
- 靶心问题、适合人群、内容基线、时间表、信息源清单由构建脚本根据 course.json 和 sources.json 自动生成，**不要手写**。

### 靶心实战页（type: capstone，放在第 2 幕最后一页）

- `hook`：把靶心问题落成一个具体场景，要有具体数字或配置。
- `<section data-block="task" data-minutes="10">`：分步骤的动手任务，最后用 `<details>` 放参考答案。`data-minutes` 写你认为的真实耗时，上限 20。
- `figure`、`points`、`retell` 同概念页。
- 这一页用前面学到的元概念真正把靶心问题解决掉，学习闭环就在这里完成。

### 费曼验收页（type: review，id 以 99 开头）

- `<figure data-block="mindmap">`：全课的概念地图，按四幕结构展开，元概念放在中心。
- `retell-set`：3–5 个 `<div class="q">`，题目用“不看材料，用大白话向外行解释 X”，折叠里放“对照要点”。
- `sticking`：学习者最容易讲不下去的 3 个地方，每个配一句提示。
- `further`：3–5 个往下挖的资源，每个带 `<cite>`。
- 类比库（全部类比及其失效处，末尾留 2 行空白）和事实核查说明由构建脚本自动生成。

## 引用

在它所支持的那句话末尾写 `<cite data-src="S3"></cite>`，多个来源用逗号分隔：`data-src="S1,S4"`。构建脚本会把它编成页内序号上标，并在页尾生成“本页来源”。每个概念页至少引用一次；数字、默认值、版本事实和强断言都要就近标出来源。

## 写作规则

- **核心正文要短。** lede、hook、anchor、points、analogy、boundary 加起来控制在约 450 字以内，超出部分挪进深入层。原因：学习者大多在手机上看，机制应该由图承担，文字只负责引导和收束。
- **术语不裸奔。** 术语第一次出现时，同一句里就给出大白话解释，比如“ISR（跟得上进度的副本名单）”。
- **一页一个知识点。** 需要两张图才能讲清两个机制时，就拆成两页。
- **转译，不搬运。** 不要整段照抄来源；原文引用只放在台账的 evidence 里。
- **不用颜色指代图的某部分。** 写“最上面那段”“标着 ISR 的方框”，不要写“蓝色那段”，因为主题和深色模式会改变颜色。
- **数字前后一致。** 页面、图、自测答案、验收要点里的同一个数，取整方式要统一，并和台账一致；约数前加“约”。
- **按学习者水平调深度。** 零基础：核心层只用生活类比，不出现未经解释的术语。有相邻经验：锚点直接落在他熟悉的领域上，深入层可以更技术。

## 代码类主题

学编程框架、中间件时，代码不能硬塞进图里，也不该铺满核心层。

- **概念页**：核心层仍然用图讲机制；最小可用的代码片段放在 `deep` 或 `task` 里，写成 `<pre><code>…</code></pre>`，每段不超过 15 行，用注释标出和本页机制对应的那一行。代码里的 `<`、`>`、`&` 要转义。
- **实战页**：完整的配置清单或代码骨架放在 `task` 里，参考答案放进折叠区块。
- 手机上代码块会横向滚动，这是正常的，不会导致页面整体溢出。
- 代码里的配置名、默认值和 API 行为同样要进台账。

## 时长模型（由构建脚本计算）

| 内容 | 计时 |
|---|---|
| 核心文字（含图注） | 每分钟约 250 字 |
| 每张图（figure、recap、mindmap 里的 SVG） | 2 分钟 |
| 每道自测题 | 1.5 分钟 |
| 复述挑战 | 3 分钟 |
| 动手任务 | 按 `data-minutes` 计，上限 20 |
| 验收页每道复述题 | 3 分钟 |
| 深入层 | 按字数单独计，作为“选读”显示 |

以三小时为目标时，一个概念页通常 8–12 分钟（约 300 字核心文字、1 张图、2 道自测、1 次复述）。核心总时长和 `target_minutes` 相差超过 25% 时，检查脚本会给出警告：增删页面，或者如实告诉用户真实时长。不要为了凑时长往页面里注水。
