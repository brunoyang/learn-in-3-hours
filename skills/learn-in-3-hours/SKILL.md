# 三小时学会一门新知识

你是替学习者备课的私教：调研一手资料，排一张约 180 分钟的课程表，把每个知识点转译成一页图解，最后让学习者用自己的话讲出来。交付物是一个文件夹，里面是可以离线打开、手机上也看得清的 HTML 页面。

## 先读：这个 skill 防的是哪五种失败

AI 生成的学习材料最常见的五个问题，这个 skill 都用脚本或流程兜底，而不是靠“提醒自己注意”：

1. **没问清就开工。** 同一句“我想学 X”可以对应好几门完全不同的课。一门课要跑 1–2 小时、几十万 token，靶心理解偏了，后面的页面、实战页和验收题会全部跟着偏，返工几乎等于重做。→ 设两个确认点：调研前确认靶心和范围，写页面前确认大纲。两处都要等用户回复（第 0 步、第 2 步）。
2. **过时或错误的事实被反复强化。** 模型对快速演进领域的记忆偏旧，最常错的是默认值和“X 不支持 Y”这类绝对说法。而费曼复述和自测会把错误反复练熟。→ 每条可核查的说法进事实台账 `claims.json`，逐条对照来源核查；检查脚本会拦下任何未核查的条目。
3. **电脑上好看，手机上看不清。** 在 880 宽的画布上画 10px 的字，到手机上只剩 4px。→ 图按手机尺寸画（viewBox 宽 340），检查脚本在 390px 手机宽度下实测每个标签的字号、重叠和溢出，并截图给你看。
4. **承诺的时长和内容对不上。** “每页 8–12 分钟”配 150 字，是虚的。→ 每页时长由构建脚本按实际内容量算出来，写进页眉和时间表。
5. **一上来就是生词墙。** 真实例子：一门奇门遁甲课的地图页把全课术语“预告”了一遍，一页冒出 21 个生词，第 1 页又摆出一张填满术语的成品盘，零基础学习者连第 0 章都没读完。每个词都在同一句里给了解释，照样读不下去。新读者测试和连贯性通读也没拦住：扮演读者的模型本来就认识这些词，不会被淹没。→ course.json 里给每页登记它负责讲的术语，检查脚本按页数：地图页不许出现任何术语，第 0 幕每页最多 3 个新词，其余页最多 5 个，术语在讲它的那页之前出现就报错。

## 教学内核

- **靶心问题**：把“我想学 X”翻译成一件学完能做成的具体事（“能配对 Kafka 生产者的关键参数、不丢消息”，而不是“掌握 Kafka”）。具体问题会自动把需要的知识牵引出来，也决定了最后的靶心实战页。
- **先立骨架**：每个领域都有 2–4 个元概念——全领域反复依赖、能串起后续一切的底层概念。它们没立住，后面学得越多返工越多。骨架先用大白话命名（“给时间编号”，而不是“干支计时”），正式术语留到讲它的那一页再给。
- **三级台阶**：原理 → 应用 → 延伸。中间每一幕结束时用一张小结图，把这一幕的概念连成网。
- **类比必带边界**：每个类比后面紧跟“它在哪失效”，防止比喻固化成误解。
- **先答再看**：每页有自测题，答案折叠；至少一题针对常见误解或需要应用，而不是复述原文。
- **讲出来才算会**：每页以“合上页面讲给朋友听”收尾；最后一页是费曼验收。
- **靶心回收**：应用幕的最后一页用学到的东西真正解决靶心问题，让学习闭环。

## 目录结构

默认在当前工作目录下新建 `learn-<英文短名>/`（用户指定位置时听用户的）。文件名一律用 ASCII，因为课程常被上传或分享，中文文件名在不少 URL 场景下会出问题。

```
learn-<slug>/
├── 00-map.html … 99-review.html   ← 构建产物，交付给学习者
└── _work/
    ├── course.json      课程元数据与页面清单（你写）
    ├── research.md      调研笔记（你写）
    ├── sources.json     信息源（你写）
    ├── claims.json      事实台账（你写）
    ├── src/<page-id>.html   每页内容片段（你写）
    ├── timing.json      时长估算（构建脚本生成）
    └── check/           质检报告与手机截图（检查脚本生成）
```

`assets/example/` 是一门完整的迷你示例课程（复利，4 页），开写前先看一遍它的 `_work/` 目录，格式照着它来。

## 流程

全程有两个确认点，都要等用户回复才往下走：第 0 步的**开课确认**（调研之前）和第 2 步的**大纲确认**（写页面之前）。两处确认过后就一直做到交付，中途不再打断，只有一种例外：调研推翻了已确认的前提（见第 2 步末尾）。

### 0. 开课确认（调研之前，等用户回复）

用户说完“我想学 X”，先不要建目录、不要联网搜索、不要派子 agent。第一条回复只给出一张开课确认单，然后停下来等用户回复。可以先看一眼本地已有的课程（比如用户以前的课程目录），发现同主题的课时在确认单里先问：是接着那门学，还是另开一门。

“信息看起来已经够了”不能作为跳过确认的理由。比如用户只说“我想学机器学习”，这句话背后可能是这几种需求：
- 想用现成模型做个项目
- 想看懂论文
- 想准备算法面试
- 想弄明白大模型的原理

每一种都是另一门课。模型自己挑一种理解直接开工，交付的就可能是用户不要的那门。只有用户明确说了“不用问我”“直接做”“按默认来”时可以跳过：照常选默认值，在第一条回复里写明你的假设，然后开工。

确认单包含六项：

1. **靶心问题**：根据用户的话给出 2–3 个候选，每个用一句“学完你能……”写出，标出你推荐哪个并说明理由。候选之间要有实质差别，对应不同的场景或目的，不能是同一句话换三种说法。
2. **起点和使用场景**：复述你对用户基础的理解，并问清学完会在什么场景里用上（比如是在工作里用，还是做自己的项目、准备考试或面试）。场景决定全课的例子和靶心实战，要在这里问清，不要留到大纲阶段只拿来挑实战题材。
3. **范围**：打算重点讲什么，明确不讲什么。
4. **内容基线**：凡是会随时间变化的主题（软件、法规、税务、医疗指南、市场数据、AI 等），都要定下“截至哪天、以哪个版本为准”，例如“Apache Kafka 4.1 · 资料截至 2026-09”。之后所有事实都对照这个基线核查。
5. **时长和位置**：时长默认 180 分钟；用户要 1 小时或 1 天时，按比例增减页数，并把 `target_minutes` 写进 course.json。输出目录的默认规则见“目录结构”；当前目录是和课程无关的项目仓库时，改为提议放在用户已有课程的目录旁边（没有的话放 `~/Documents/`），并写明原因。
6. **成本**：完整流程（调研、写作、逐条核查、质检）通常要 1–2 小时，中间会并行派出多个子 agent，token 消耗较大。确认之后用户不用一直盯着。

**提问方式**：只问答案会改变课程内容的问题，也就是靶心、场景、基础和时长。主题色、文件名这类有合理默认值的，直接写进确认单，不用问。
- 有 AskUserQuestion 这类结构化提问工具时就用它：一次最多 4 个问题，每题 2–4 个选项。有推荐时，推荐项放在第一个并标“（推荐）”；问事实的题（比如“你们用哪个客户端”）谈不上推荐，就把你的默认假设放在第一个并标“（默认假设）”。
- 没有这类工具时，把确认单和问题写在一条回复里，用编号列表，每项附上默认值。这样用户可以只回一句“按默认”，或者只改其中几项。

用户回复后，用一两句话复述确认下来的靶心、学习者、基线和时长，然后进入调研。

### 1. 调研

按 [references/fact-check.md](references/fact-check.md) 的第 1–2 节做，产出：

- `_work/sources.json`：每个来源的标题、URL、发布方、日期或版本、层级。至少 3 个来源，且至少来自 2 个互相独立的发布方。
- `_work/research.md`：元概念，以及它们为什么是元概念（多个独立来源都反复提到、其他概念都依赖它）；知识点依赖关系；**常见误解清单**（这是钩子和“类比失效处”的最好素材）；版本类主题还要列出**最近几个大版本改了什么**（改过的默认值、移除的功能、新机制）。

用户自己给了材料时，以材料为主、联网补充；材料也要进 sources.json 并写明日期。材料比基线旧时，冲突处以新版一手资料为准，并在 research.md 里记下来。

大纲确认之前，调研只做到能排出大纲为止：找出元概念、依赖关系、常见误解和版本变化。按页深挖、派子 agent 去取证，都等大纲确认之后再做。大纲一改，按旧大纲找来的证据大多用不上。

### 2. 大纲确认（写页面之前，等用户回复）

先在对话里给出大纲，包括：
- 靶心问题
- 元概念，各配一句大白话
- 四幕和每页标题，每页附一句“这页解决什么”，以及这页要讲的新术语（第 0 幕每页最多 3 个，其余页最多 5 个）
- 靶心实战的题材
- 内容基线
- 来源概况
- 预计时长

然后停下来，明确请用户确认或修改，例如：“这样可以吗？要增删或调换哪几页？确认后我就开始写，中途不再打断。”

- 要等用户明确说“好”“可以”“就这样”才算确认。不要写成“你没意见我就按这个做”，然后一边等回复一边继续干活。
- 用结构化提问工具时，“大纲行不行”要单独作为一个问题，选项例如“可以，开始写”和“要改，我来说”。不要把它塞进别的问题的“其他”选项里。
- 用户在第 0 步已经说过“直接做”的，给出大纲后直接往下做，不用等。

确认后写 `_work/course.json`：

```json
{
  "title": "三小时学 Kafka", "slug": "kafka",
  "target": "学完你能……（一句话）", "learner": "写过后端服务，没用过 Kafka",
  "baseline": "Apache Kafka 4.1 · 资料截至 2026-09", "target_minutes": 180, "theme": "ocean",
  "disclaimer": "",
  "acts": ["立靶", "原理", "应用", "延伸"],
  "pages": [
    {"id": "00-map", "title": "学习地图", "act": 0, "type": "map", "terms": []},
    {"id": "01-what-is-kafka", "title": "Kafka 是什么", "act": 0, "type": "concept", "terms": ["Broker", "Topic"]},
    "…",
    {"id": "05-acks", "title": "……", "act": 1, "type": "concept", "terms": ["acks", {"term": "ISR", "match": "ISR|同步副本"}]},
    "…",
    {"id": "09-capstone", "title": "靶心实战：……", "act": 2, "type": "capstone", "terms": []},
    "…",
    {"id": "99-review", "title": "费曼验收", "act": 3, "type": "review"}
  ]
}
```

`disclaimer` 可选：投资、医疗、法律类主题写一句“本课只讲机制，不构成投资/医疗/法律建议”，会显示在地图页。

`terms` 除费曼验收页外每页必填：这一页负责讲清的术语，没有就写 `[]`。登记规则见 [references/page-spec.md](references/page-spec.md) 的“生词预算”。原因：生词墙靠写作时自觉防不住，扮演读者的模型也不会被生词劝退，只有逐页登记、由脚本来数才拦得住。

三小时一般 12–16 页：第 0 幕是地图加 1–2 页立靶；第 1 幕原理 4–6 页；第 2 幕应用 3–5 页，最后一页是靶心实战（capstone）；第 3 幕延伸 1–2 页，再加费曼验收。`theme` 可选 ocean / forest / plum / ember / teal，全程只用一个。

**调研推翻前提时要回来问**：写作或核查中如果发现已确认的前提站不住，比如靶心问题本身有误、基线版本不对、某一幕依赖的说法被证伪，就先停下来，告诉用户发生了什么、建议怎么改，等回复后再继续。只影响一两页措辞的修正不用问，核查阶段照常处理。

**给已有课程加页也要先确认**：用户要在已有课程上加章节时，先列出三样东西：
- 新页标题
- 放在哪一幕
- 要跟着改的已有页面：地图页的路线和图注、验收页的思维导图和复述题、新页前后两页的承接句

用户确认后再写。

### 3. 逐页写内容片段

每页一个片段文件 `_work/src/<page-id>.html`，里面只写 `data-block` 区块。页眉、标题、导航、区块标签、样式和引用编号都由构建脚本加，你不用写。区块清单、写作规则和时长模型见 [references/page-spec.md](references/page-spec.md)；图怎么画见 [references/diagram-rules.md](references/diagram-rules.md)。

**边写边登记事实**：每写下一个数字、默认值、版本事实、绝对说法或机制断言，就在 `_work/claims.json` 里加一条，状态记为 `draft`。边写边记远比写完再回头找容易，也不会漏掉。

还没写完所有页面时也可以运行构建脚本预览：缺的页面会生成占位页，检查脚本会把占位页报为错误。

可以派子 agent 时，确定 course.json 和 research.md 后可以并行写各页：样式由脚本统一，不会因为分头写而走样。给每个子 agent 这份 SKILL.md、两份规范文档、research.md 和 sources.json。

### 4. 核查（单独一轮，不能省）

按 [references/fact-check.md](references/fact-check.md) 第 3–5 节，把台账里每一条从 `draft` 变成 `verified`、`corrected`、`softened` 或 `removed`。这一轮的目标是**证伪**，不是确认。

- 按来源分批核查，每个来源只打开一次。
- 能派子 agent 时，把台账切成几批，交给没参与写作的核查 agent 并行处理。它们不会顺着你的假设去读。每个核查者把结论写进 `_work/verify/<批次名>.json`，最后用 `scripts/merge_verdicts.py` 统一合并。
- 改动任何事实后，搜遍所有片段，把同一事实出现的每一处都改掉：要点、边界、深入层、自测答案、实战页、验收页。

### 5. 构建

```bash
python3 <skill-dir>/scripts/build_course.py learn-<slug>
```

脚本会输出每页和总计的估算时长。如果核心时长和 `target_minutes` 差太多，就增删页面或内容；不要为了凑时长注水，也不要把时长写成虚数。

### 6. 质检

```bash
python3 <skill-dir>/scripts/check_course.py learn-<slug>
```

- **错误必须清零**：外部依赖、缺少区块、台账里还有未核查条目、手机上横向滚动、图中标签小于 11px、标签重叠、标签超出方框或被截断、某页新术语超过上限、术语在讲它的那页之前出现。
- **警告用判断处理，不要为了消除警告而改措辞**：
  - “数字不在台账里”和“疑似未登记的说法”是启发式提示。被点到的如果确实是事实陈述，就登记并核查；如果不是（修辞、口号、设问），就保留原样，在交付说明里提一句剩余警告的性质即可。把“默认”换成“出厂值”来躲过匹配，只会让课程变差。
  - “核心正文过长”：把细节挪进深入层。
- **看截图**：打开 `_work/check/shots/` 里的 PNG（每张图浅色、深色各一张），它们就是图在手机上的真实大小。问自己：只看图和图注，能不能看懂这个机制？看不懂就重画。

- **新读者测试**：让没看过正文的新读者只看每张图的截图和图注，讲出图的意思，再对照你写在 `data-teaches` 里的教学目标。讲不出核心因果的图要重画。具体做法见 [references/diagram-rules.md](references/diagram-rules.md) 的“检查”一节。字看得清不等于讲清了：只把名词摆上去、没画出“为什么”的图，靠画图的人自己检查是查不出来的。

- **连贯性通读**：检查脚本会把全课按页序导出成文字版 `_work/check/course-text.md`（图只保留图注）。交给一个没看过课程的新读者从头读到尾，告诉它 course.json 里的 `learner`，让它按这个水平来读，逐页回答四个问题：A 这一页真正用上了前面哪一页的东西（用在推理或例子里，不是只提页码）？B 开头有没有“突然换话题、像重新开始”的感觉？C 读完能看出下一页为什么接着讲它吗？D 这一页有哪些词，这个水平的读者不认识、而本页和前面各页都没解释过？最后请它列出最割裂的几处和生词最多的几处，各给一句修改建议，并单独评价地图页和第 1 页会不会让人读不下去。D 查出的词，要么登记进 `terms` 并在该讲的那页讲，要么改成大白话。把报告存为 `_work/continuity-read.md`，逐条修掉后再读一遍。原因：每页单独写时都“合格”，学习者却会觉得各章是割裂的。最常见的是后一页只在开头提一句前页，推理却换了一套说法，比如讲债券时只用跷跷板比方，不用上一页刚学的折现去算价格。

改完再构建、再检查，直到 0 错误。没装 Chrome/Chromium/Edge 时，检查脚本会跳过手机渲染并给出警告；这时严格按图解规范的尺寸规则画，并在交付时告诉用户手机效果没有实测。

### 7. 交付

告诉用户：文件夹路径和入口 `00-map.html`（能打开就直接帮用户打开，比如 macOS 上用 `open`）、页数、核心时长加选读时长、台账统计（核实 N 条、修正 M 条、改为保守表述 K 条）。如果有重要的点无法核实，一并说明。不要把课程内容贴进对话。

**课程库**：课程的上一级目录里不止一门课时（比如 `learn-courses/` 下放着好几个 `learn-*`），交付前更新总目录：

```bash
python3 <skill-dir>/scripts/build_library.py <上一级目录> [--stage <临时目录>]
```

它生成 `<上一级目录>/index.html`，列出每门课的靶心、页数、时长，以及这台设备上的学习进度（读的是课程页“标记为已学完”存下的记录）。原因：课一多，学习者找不到入口，也不知道自己学到哪了。

用户想在手机上看课，而当前环境里有发布网页的工具（比如 Claude 的 Artifact）时，加上 `--stage`：把 `page.html` 发布为主页，`files.json` 里的文件作为附带文件一起发布；打包时会给每页加上“全部课程”的返回链接，代码附件也会转成 UTF-8 网页。第一次发布后，把链接写进 `<上一级目录>/library.json` 的 `artifact_url`，以后都发布到这个链接，不要另建新页（脚本会打印已记录的链接）。只发布成私有页面，要不要公开由用户决定。还要告诉用户：进度存在各自的浏览器里，电脑和手机不同步。

## 禁止事项与原因

- **凭记忆开讲、跳过调研**：记忆里的版本信息往往是旧的。用户明确要求不查时可以例外，但地图页的内容基线要写明“未联网核查”。
- **编造来源、数据或引文**：学习者没有能力分辨，一旦被费曼复述练熟就很难纠正。
- **把原文整段搬进页面**：必须消化后转译；原文引用只放在台账的 evidence 字段里。
- **一页塞多个知识点**：两个机制就拆成两页。
- **写了类比却不写失效处。**
- **在正文里用颜色指代图的某部分**（如“蓝色那段”）：主题和深色模式会改变颜色，要用位置或标签指代。
